📥 LaunchMate Drops Naming Convention

Asset Type: Documentation • Generated: April 29, 2026

Drops are artifacts generated from transcript analysis and scheduled for delivery. This guide defines the folder structure and naming conventions for the drops repository.

Folder Structure

drops/
├── {cohort}/ # e.g., inflight-spring-26
│ ├── {user}/ # e.g., laura-wetherhold
│ │ ├── {drop-type}-{date}.{ext} # actual drop files
├── templates/ # Reusable templates
├── staging/ # Pre-delivery staging area
└── archive/ # Old drops (1+ years)

Drop Types

Type Description Example
briefing Meeting summary with key insights and commitments briefing-2026-04-29.html
reminder Follow-up on explicit commitments reminder-2026-04-30.txt
asset Generated guides, templates, or documentation asset-2026-04-29.html
research Compiled research or contact lists research-2026-04-29.json
drop Generic artifact (use specific types when possible) drop-2026-04-29.md

File Extensions

Extension Use Case
.html Rich formatted content (briefings, assets, guides)
.md Simple text, notes, documentation
.txt Plain text reminders, simple messages
.json Structured data (research, contacts, configurations)
.pdf Formal documents, reports

Examples

Meeting Briefing for Laura
inflight-spring-26/laura-wetherhold/briefing-2026-04-29.html
Rich HTML summary of strategic planning meeting with Craig and Michael
Reminder for Craig
inflight-spring-26/craig-lauer/reminder-2026-04-30.txt
Plain text reminder about reaching out to interns
Research Asset
inflight-spring-26/laura-wetherhold/research-2026-04-29.json
JSON data of 10 boat marinas in San Diego with contact info

Staging Area

Before drops are finalized and moved to their final location, they can be staged in:

staging/{drop-id}/
├── metadata.json # Drop metadata (type, recipients, schedule)
├── content.html # Actual drop content
└── status.txt # pending | ready | delivered

Archive Policy

Drops older than 1 year are automatically moved to:

archive/{year}/{cohort}/{user}/

Integration Points

  • Transcript Agent → sends analysis to Drop Agent
  • Drop Agent → creates drop metadata + schedules delivery
  • GitHub API → stores artifacts in drops repo
  • Founder Agents → receive notification of drop delivery
